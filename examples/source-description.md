# Описание синтетического учебного случая

Сеть сервисных центров принимает заявки клиентов. Одна заявка относится ровно к одному зарегистрированному клиенту, филиалу и статусу. У клиента и филиала может не быть заявок. Номер заявки уникален и непуст; внутренний числовой id не обязан совпадать с числом внутри её номера.

Входные CSV кодируются UTF-8, разделитель — запятая, кавычки — двойные. Первая строка содержит имена полей. Номер `source_row` считает строки данных, без заголовка. Сохраняются исходные файлы и их порядок. Три файла:

| Файл | Поля | Строк данных |
| --- | --- | --- |
| branches.csv | code,name | 3 |
| clients.csv | code,name | 2 |
| requests.csv | request_no,client_code,branch_code,status_code,received_at,part_codes | 6 |

Коды справочников уникальны и обязательны. Название не является идентификатором: B01 и B03 намеренно имеют одинаковое name «Северный сервис». В заявках используется branch_code, соединение по названию не допускается. Имена клиентов синтетические.

Допустимые статусы заданы описанием: NEW — новая, WORK — в работе, CLOSED — закрыта. Допустимые детали: P01 и P07. Виды работ: DIAG — диагностика, REPAIR — ремонт. Их нет в отдельных входных CSV; они создаются как согласованные справочники, а не угадываются по частоте значений.

`received_at` имеет формат `YYYY-MM-DD HH:MM:SS` и должен быть календарно допустим в диапазоне DATETIME стенда. Данные представлены как единый учебный календарь без преобразования временных зон. Правило межфилиального времени в реальной системе потребовало бы отдельного согласования; текущий набор его не устанавливает. Запрет будущих дат не задан.

В `part_codes` один или два различных кода через `;`. Каждый код в этом наборе означает ровно одну единицу детали; повтор кода, неизвестный код и пустой список не допускаются. Это ограниченное учебное правило. Учёт партий, повторных позиций или количества потребовал бы расширения формата. В SQL допустимы ровно P01, P07, P01;P07 и P07;P01.

В первичном импорте первой считается строка данного номера с наименьшим `source_row`. Последующие строки номера отклоняются; исправления, слияние и обновления из следующей поставки не выполняются скрыто. Если первая строка недопустима, выбор «первой корректной» без нового правила не производится. Приоритет основной причины отказа: пустой номер, неизвестные филиал/клиент/статус, неправильная дата, неправильный список деталей, повтор номера. Одна основная причина не перечисляет обязательно все проблемы строки.

Приняты R101/C01/B01/NEW, R102/C02/B01/WORK и R103/C01/B02/CLOSED. Отклонены строки 4 (B99), 5 (пустой номер), 6 (повтор R101). Итого 6 = 3 принято + 3 отклонено. В request_parts четыре позиции: R101/P01, R101/P07, R102/P01, R103/P07, quantity=1. Для исходной закрытой R103 имеется работа REPAIR. До опытов изменения журнал статусов пуст.

Примеры оборудования и инженера в лекциях являются обозначенными расширениями требований. Они не считаются таблицами базового стенда. Базовый DDL создаёт 13 таблиц и 8 FK. Отдельный опыт индекса создаёт requests_plan с 10 000 синтетическими строками; эта таблица не является ещё одной сущностью исходной сервисной модели.
